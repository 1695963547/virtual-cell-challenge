重要：哪些是原始数据，哪些是我加的
----------------------------------
原始 h5 文件里没有「表格」，只有这些数组:
    X/data, X/indices, X/indptr   稀疏表达矩阵
    obs/target_gene               每个细胞被敲的基因名(纯字符串)
    obs/guide_id, obs/batch_var, obs/cell_type
    var/_index                    18080 个基因名

下面这些是我为了方便阅读加工出来的，原文件里没有:
  - CSV 这个形式本身（原文件是 HDF5 二进制）
  - group 列的中文字样「XXX被敲低」/「对照(non-targeting)」
        原始数据只有 target_gene = "TMSB4X" 或 "non-targeting"
  - 「还原成UMI计数」列（我用 e^值-1 算的）
  - cell_1 / control_1 这种行标签（原始是 barcode 字符串）


为什么 first50genes 两个文件看起来差不多
----------------------------------------
实测 TMSB4X 敲低对 18080 个基因的影响:
    靶基因 TMSB4X 本身  4.624 -> 1.210  (-3.414)
    最强连带基因 SPCS1  2.274 -> 1.782  (-0.492)
    前 50 个基因平均绝对变化      0.0245
    全部基因平均绝对变化          0.0233
扰动效应几乎全部集中在靶基因自己身上。前 50 个基因跟 TMSB4X 无关，
变化只有 0.02 量级，而单细胞随机噪声是 ±1.0 量级，肉眼必然看不出差别。
这是生物学事实，不是文件出错。要看差别只能看靶基因那一列。


文件说明
--------
train_obs_前300个细胞.csv
    训练集的细胞元数据表。一行 = 一个细胞。
    target_gene = 这个细胞被敲低了哪个基因，non-targeting = 对照
    guide_id    = 用的哪条 sgRNA，batch_var = 测序批次
    完整文件有 221273 行（细胞）。

train_matrix_first50genes.csv
    表达矩阵长什么样：行 = 细胞，列 = 基因，值 = 表达量。
    只取了前 50 个基因，能看到大量 0.0 —— 真实数据 ~90% 是 0（稀疏）。
    完整矩阵是 221273 行 × 18080 列。

train_matrix_TMSB4X_vs_control.csv
    ★ 最能说明任务是什么的一张表。
    前 12 行是 TMSB4X 被敲低的细胞，后 12 行是对照细胞。
    看第 3 列 TMSB4X：敲低组 0.0~1.6，对照组 3.6~5.2 —— 基因确实被敲下去了。
    后面 39 列是高表达基因，用来看敲低带来的连带变化。

train_稀疏存储长表.csv
    文件在磁盘上的真实存储形态：只存非零值的 (细胞, 基因, 值) 三元组。
    这就是 h5 里 X/data + X/indices + X/indptr 三个数组的含义。
    附了一列还原成 UMI 整数计数。

train_靶基因清单.csv
    训练集 150 个靶基因 + 每个基因有多少细胞。
    non-targeting 对照细胞最多（38176 个）。

test_template_obs_前300个细胞.csv
    测试模板（答题卡）的元数据。只告诉你「要预测哪个基因、预测多少个细胞」。

test_template_matrix_GRB10_vs_control.csv
    ★★ 最容易误解的文件，务必看清楚 ★★
    group 列写「要预测GRB10敲低(数字是对照细胞占位符_非实测)」，意思是:
        这一行【应该】是个 GRB10 敲低细胞，但格子里的数字是假的。

    实测证据（逐字节比对，2026-07-29）:
        GRB10 组前 8 个细胞里有 7 个是对照细胞的完整副本，一个数字都不差:
            GRB10_pert_1 == 第 146512 行(对照)
            GRB10_pert_2 == 第 133497 行(对照)
            GRB10_pert_3 == 第 150434 行(对照)
            GRB10_pert_4 == 第 160145 行(对照)
            GRB10_pert_5 == 第 140491 行(对照)
            GRB10_pert_7 == 第 149361 行(对照)
            GRB10_pert_8 == 第 150649 行(对照)
        剩下的 pert_6 的 GRB10 = 1.6094，比对照均值 1.5549 还高，也没被敲低。

    对比 train_matrix_TMSB4X_vs_control.csv 里真正的实测敲低:
        敲低组 TMSB4X = 1.61 1.39 0.69 0.69 ...
        对照组 TMSB4X = 4.36 4.78 5.12 4.42 ...   ← 塌了一大截，这才是真数据
    而模板里:
        "敲低"组 GRB10 = 1.61 2.20 1.39 2.30 ...
        对照组   GRB10 = 1.95 1.95 1.61 0.00 ...   ← 分不开

    官方为什么塞对照细胞而不填 0:
        很多模型（含 STATE）需要一个 basal 表达谱当输入起点，填 0 会让流程跑不动。
    真正的答案在 adata_Test.h5ad 里，比赛期间不公开，防止抄答案。

靶基因三集合划分.csv
    train 150 / val 50 / test 100 个靶基因，三者完全不重叠。
    模型必须预测训练时从没见过的基因 —— 这是零样本泛化。

truth_*.csv
    真值 adata_Test.h5ad 的切片，等文件下完再跑一次脚本就会生成。
    它是原始整数计数（不是 log1p），只在最后打分时用。


推理的时候模型到底输入什么
--------------------------
代码依据: state/src/state/_cli/_tx/_infer.py 第 814-819 行

    sampled_ctrl_idx = rng.choice(grp_ctrl_pool, size=win_size, replace=True)
    ctrl_basal = X_in[sampled_ctrl_idx, :]      # 只取对照细胞的行
    pert_oh = vec.float().unsqueeze(0).repeat(win_size, 1)   # 靶基因 one-hot

输入只有两样东西:
  1. 一个对照细胞的真实表达谱（18080 维，从模板的 non-targeting 行随机抽）
  2. 一个靶基因 one-hot（“这次要敲 GRB10”）

输出: 该细胞被敲低后的 18080 维表达谱，写回对应行。
      整个测试集要输出 132670 个细胞 × 18080 个基因。

注意: 模型从不读取「被扰动细胞」那一行的 X。所以模板里的占位数据
      是什么完全不影响推理，也证明模板里没有答案泄露。
